# Publication Boundary

The companion repo is meant to be public-facing.

That only works if the boundary is strict.

## Safe to publish

- article titles, URLs and public publication dates
- technical setup summaries
- methodology summaries
- insights at article level
- dataset source references
- demo schemas and example queries
- scripts that work only on public metadata or reader-supplied data

## Keep in the private working repo

- local workstation paths
- WordPress publishing scripts
- unpublished article drafts
- private HTML snapshots and intermediate files
- internal editorial notes
- credentials, tokens and auth helpers
- third-party raw datasets that should not be redistributed
- any leak-derived material that should be referenced but not mirrored here

## Practical rule

If a file would make sense to a motivated reader without access to the internal
workspace, it is a candidate for the companion repo.

If it only makes sense inside the editorial workshop, it stays private.
